---
title: 可插拔架构实战：Factory + 抽象层
---

本文用 `mem0/utils/factory.py` 与 `mem0/vector_stores/base.py` 两个核心文件，拆解 Mem0 如何做到「同一套业务逻辑，替换不同后端提供商」。

## 1. 一眼看懂核心设计

Mem0 的可插拔能力主要来自两层：

1. **Factory（工厂层）**：负责“按 provider 名字 → 动态加载实现类 → 组装配置 → 返回实例”。
2. **抽象基类（协议层）**：定义统一能力边界（例如向量库要支持创建集合、插入、搜索、删除等）。

对应到代码：

- 工厂汇总：`LlmFactory`、`EmbedderFactory`、`VectorStoreFactory`、`GraphStoreFactory`、`RerankerFactory`。
- 抽象接口：`VectorStoreBase`。

---

## 2. Factory 是如何工作的（逐步拆解）

### Step A：provider 注册表（provider_to_class）

每个 Factory 内部都有一张映射表，把 provider 字符串映射到“实现类路径（有时还带 config 类）”。

例如：

- LLM: `"openai" -> ("mem0.llms.openai.OpenAILLM", OpenAIConfig)`
- Vector Store: `"qdrant" -> "mem0.vector_stores.qdrant.Qdrant"`

这意味着：业务层不需要 `if/elif` 写满各种后端分支，只要传 provider 字符串即可。

### Step B：load_class 动态导入

`load_class(class_type)` 会做两件事：

1. `module_path, class_name = class_type.rsplit('.', 1)`
2. `importlib.import_module(module_path)` 后 `getattr(module, class_name)`

所以工厂拿到字符串路径就能实例化目标类。

### Step C：配置归一化

以 `LlmFactory.create()` 为例，支持多种入参：

- `config is None`：按 provider 对应配置类 + `kwargs` 生成默认 config。
- `config is dict`：与 `kwargs` 合并，再转成对应配置类。
- `config is BaseLlmConfig`：必要时转 provider-specific config（比如 OpenAI/Azure/Anthropic）。

这样就兼容了旧配置与新 provider 专属配置。

### Step D：实例化与返回

- 载入类后，`return llm_class(config)`。
- Vector store 则把 pydantic 配置 `model_dump()` 成 dict，再 `return vector_store_instance(**config)`。

最终上层拿到的是“统一可用对象”，而不是 provider 分支。

---

## 3. 抽象层怎么兜住一致性

`VectorStoreBase` 定义了向量库必须实现的方法：

- `create_col`, `insert`, `search`, `delete`, `update`, `get`
- `list_cols`, `delete_col`, `col_info`, `list`, `reset`

这像一份“能力合同”：

- 你可以换 Qdrant、Milvus、PGVector、Pinecone……
- 但上层 Memory 代码调用接口方式不变。

因此：**Factory 解决“怎么选后端”，抽象层解决“选完后怎么保持调用一致”。**

> 你问的关键点："所有向量数据库都必须严格实现这套接口吗？"
>
> - **设计目标上：是的**。Mem0 期望每个向量库 provider 都提供 `VectorStoreBase` 这组能力（至少语义等价）。
> - **工程实现上：是“强约束 + 运行时验证”**。内置 provider 通常继承 `VectorStoreBase`；但在 Python 里，Factory 主要按 `provider -> class` 动态实例化，真正会不会出错，仍取决于该类在运行时是否具备被调用的方法。
> - **实操结论**：如果某个 provider 缺少 `insert/search/list/reset` 等关键方法，初始化也许能通过，但在对应调用路径会在运行时报错。
>
> 所以最稳妥的扩展方式是：**新增 provider 时按 `VectorStoreBase` 完整实现（或保持语义等价）**，这样上层 Memory 才能真正做到无感切换。

## 4. 完整案例（从配置到运行）

下面给一个“可直接映射到源码行为”的完整案例：

### 场景

你要把默认向量库换成 Qdrant，把 LLM 用 OpenAI，嵌入模型也用 OpenAI。

### 配置（示意）

```python
config_dict = {
    "llm": {
        "provider": "openai",
        "config": {
            "model": "gpt-4o-mini",
            "api_key": "${OPENAI_API_KEY}",
            "temperature": 0.2,
        },
    },
    "embedder": {
        "provider": "openai",
        "config": {
            "model": "text-embedding-3-small",
            "api_key": "${OPENAI_API_KEY}",
        },
    },
    "vector_store": {
        "provider": "qdrant",
        "config": {
            "collection_name": "memories",
            "embedding_model_dims": 1536,
            "path": "/tmp/qdrant",
            "on_disk": True,
        },
    },
}
```

### 运行路径（对应 Memory 初始化）

1. `Memory.__init__` 调用 `EmbedderFactory.create(...)` 创建 embedding 模型。
2. 调用 `VectorStoreFactory.create(...)` 创建 Qdrant 实例。
3. 调用 `LlmFactory.create(...)` 创建 OpenAI LLM 实例。
4. 后续 `add/search` 等业务逻辑只依赖统一接口，不关心 provider 细节。

### 为什么这是“可插拔”

如果你把：

- `vector_store.provider` 从 `qdrant` 换成 `pgvector`
- `llm.provider` 从 `openai` 换成 `anthropic`

业务层代码几乎不用改，只是工厂映射到不同实现类。

## 5. 逐步推理演示（以 VectorStoreFactory 为例）

假设执行：

```python
store = VectorStoreFactory.create("qdrant", qdrant_config)
```

推理过程：

1. 查映射：`"qdrant" -> "mem0.vector_stores.qdrant.Qdrant"`。
2. `config` 不是 dict（通常是 pydantic model）→ `model_dump()` 转 dict。
3. 动态导入 `Qdrant` 类。
4. 执行 `Qdrant(**config)`。
5. `Qdrant.__init__` 内部会设置 client，并调用 `self.create_col(...)` 准备 collection。
6. 返回 `store`，其类型具体是 `Qdrant`，但上层可按 `VectorStoreBase` 约定来用。

这就是“**运行时绑定具体实现 + 编译时（设计时）保持统一接口**”。

## 8. 扩展一个新 provider 的最小步骤

1. 实现目标类（例如 `mem0/vector_stores/mydb.py` 的 `MyDB(VectorStoreBase)`）。
2. 在 `VectorStoreFactory.provider_to_class` 增加映射：

```python
"mydb": "mem0.vector_stores.mydb.MyDB"
```

3. 确保配置字段可由 `MyDB(**config)` 接收。

完成后，上层无需新增分支即可切换到 `provider: "mydb"`。

这就是 Mem0 工程上最精华的点之一：**把变化封装到 provider 实现里，把稳定面暴露给业务层。**
